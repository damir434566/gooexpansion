## Что это за фича

Магазины отвечают отказом (403) серверу на Vercel, но отвечают браузеру
администратора: его IP, его куки, уже пройденная проверка Cloudflare. Поэтому
добыча переносится в браузер, а решения остаются на сервере.

- **Сервер** решает, что товар, разбирает разметку и кладёт в каталог.
- **Расширение Chrome** только открывает страницы и отдаёт готовый DOM.

Это продолжение блока «добыча» из PR #863 (он уже в `master`, коммит `f3bdc17`).

### Как оно работает в двух словах

Расширение не умеет обращаться к нашему API и не содержит ключей: сессия Clerk
кросс-доменно не поедет, а токен внутри расширения — это ключ под ковриком.
Вместо этого оно говорит через `postMessage` с открытой вкладкой
`/goo-studio/parser/collect`, а та зовёт API обычной сессией админа.

Доступ к домену магазина — `optional_host_permissions` плюс запрос по клику, а
не `<all_urls>` при установке.

### Вежливость — это не опция, её нельзя «оптимизировать»

Прогон идёт с домашнего адреса человека. Бан, заработанный здесь, зарабатывается
сразу на всех магазинах и обратно не откатывается.

- `Disallow` из robots.txt соблюдается;
- пауза `max(Crawl-delay магазина, 1.5 с)` плюс случайный разброс;
- ~10 секунд отдыха каждые 20 страниц;
- два ответа 403/429 подряд — прогон останавливается и объясняет почему;
- Stop срабатывает мгновенно.

Если будешь что-то править — эти пять правил не трогай.

## Грабли

1. **`npm run dev` в проекте сломан.** Не ты сломал — известная проблема,
   записана в `AUDIT_PLAN_BRIEF.md` за 2026-08-11. `DESIGN_SYSTEM.md:78`
   содержит `text-[var(--fg-on-dark-60/70/80)]`, Tailwind v4 сканирует `.md` в
   корне и принимает это за класс, dev-загрузчик CSS падает, каждый маршрут
   отдаёт 500. **Обход: `npm run build && npm start`.** Прод не затронут —
   на сборке это предупреждение, а не ошибка.
2. **Для запуска локально нужны ключи:** Clerk, Supabase и твой Clerk user id в
   `ADMIN_USER_IDS` — иначе `requireAdmin` вернёт 401, а импорт скажет
   «Database not configured». Смотри `.env.example`.
3. **Не добавляй расширение в проверки сборки.** `extension/` — это простой
   браузерный JS, он намеренно вне `tsconfig.json` (там `include` покрывает
   только `.ts`/`.tsx`/`.mts`). ESLint его проверяет и проходит чисто.
4. **Ничего не дублируй.** `extractProductLinks`, `looksLikeProductPath`,
   `isNonProductPath` и хелперы `sitemap.ts` переиспользуются. Если понадобится
   что-то похожее — экспортируй существующее, а не копируй.

## Что выдать человеку в конце

Короткую инструкцию **на русском, без внутренностей**. Человек прямым текстом
сказал, что устройство ему неинтересно — нужен порядок действий. Примерно так:

1. **Готово и выкачено** — назвать, что именно теперь есть на сайте.
2. **Поставить расширение:** скачать папку `extension/` (можно прямо из
   репозитория), положить туда, откуда не удалит, `chrome://extensions` →
   «Режим разработчика» → «Загрузить распакованное» → выбрать папку → приколоть
   иконку булавкой.
3. **Собрать магазин:** зайти на Goo Studio админом → в другой вкладке открыть
   **страницу категории** магазина (не главную) → иконка расширения → количество
   → «Collect this store» → разрешить доступ, когда Chrome спросит.
4. **Чего ждать:** вкладка приёмника со счётчиком, фоновые вкладки мелькают и
   закрываются сами, идёт медленно и это намеренно — полторы-две секунды на
   товар плюс передышка. Сто товаров — минут пять-семь.
5. **Во время прогона:** вкладку приёмника не закрывать, компьютеру не давать
   уснуть. Сворачивать браузер и работать в других вкладках — можно.
6. **Если сломалось:** «Waiting for the extension» → перезагрузить вкладку
   приёмника (F5); «refused two pages in a row» → магазин отбивается, прогон
   встал сам, попробовать через час; Stop — в popup или на вкладке приёмника.
7. **Где результат:** товары в каталоге, `/goo-studio/products`.

Готовый текст такой инструкции уже лежит в `extension/README.md` — можно взять
оттуда, дополнив реальным адресом выкаченной страницы.

**Не пиши отчёт о проделанной работе.** Человеку нужно, что нажать.
