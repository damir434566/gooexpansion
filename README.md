Продолжение блока «добыча» из **PR #863** (`Darakhamia/goo-fashion`): магазины
отвечают отказом нашему серверу на Vercel, но отвечают браузеру администратора.
Руки переносятся на его машину, мозги остаются на сервере.

## Что сделано

### Сервер — решает, что собирать

| Файл | Что делает |
|---|---|
| `src/lib/server/parser/robots.ts` | Разбор robots.txt: Allow/Disallow по длиннейшему совпадению (с `*` и `$`), Crawl-delay, Sitemap. Только группа `*` — Googlebot'ом не представляемся. Разбор чистый, сеть не трогает. |
| `src/lib/server/parser/plan-collection.ts` | Чистая функция: страница + сайтмапы + robots → товарные адреса, пауза, что дочитать следующим кругом. |
| `src/app/api/admin/parser/collect/route.ts` | Действия `plan` и `ingest`. `ingest {url, html}` зовёт `parsePage` с готовой разметкой — в магазин не ходит; без `html` отвечает 400, а не фетчит молча. |
| `src/app/goo-studio/parser/collect/page.tsx` | Вкладка-приёмник: мост postMessage ↔ API обычной сессией Clerk, живой ход прогона, исходы по страницам, Stop. |

Ничего не продублировано: `extractProductLinks`, `looksLikeProductPath`,
`isNonProductPath` и хелперы `sitemap.ts` переиспользованы (для этого из
`sitemap.ts` экспортированы `locations`, `isIndex`, `namesProducts`, `rankChild`
и `CANDIDATES`). Заодно исчез дубль: `fromRobots` в `sitemap.ts` разбирал строки
`Sitemap:` сам — теперь зовёт `parseRobots`.

Изменены всего два существующих файла: `sitemap.ts` (экспорты + снятый дубль) и
`audit.ts` (одна строка в union `AdminAction`).

### Расширение — `extension/`, manifest v3

| Файл | Что делает |
|---|---|
| `manifest.json` | `optional_host_permissions`, **не** `<all_urls>`. Content script — только на `/goo-studio/parser/collect*`. |
| `popup.js` / `popup.html` / `popup.css` | Сколько собрать, «Collect this store», прогресс, Stop. Здесь же запрос доступа к домену по клику. |
| `background.js` | Очередь, темп, вкладка → отрисовка → снять DOM → закрыть. Вся вежливость. |
| `snapshot.js` | Санитайзер: скрипты кроме `ld+json`, стили, svg, iframe, data-URI — один в один с `src/lib/parser-bookmarklet.ts`. Сначала прокручивает страницу, чтобы проснулась ленивая галерея. |
| `bridge.js` | Мост между воркером и вкладкой-приёмником. |

**Ключей в расширении нет.** Оно не умеет звать наш API: сессия Clerk
кросс-доменно не поедет, а токен внутри расширения — ключ под ковриком. Оно
говорит с открытой вкладкой приёмника, а та зовёт API вашей обычной сессией.

### Вежливость

- Disallow из robots.txt соблюдается — решает сервер, расширение не может обойти.
- Пауза `max(Crawl-delay магазина, 1.5 с)` + случайный разброс.
- Отдых ~10 с каждые 20 страниц.
- Два ответа 403/429 подряд — остановка с объяснением.
- Stop мгновенный: гасит текущую паузу **и** приёмник перестаёт принимать, так
  что страница «в полёте» уже не долетит до импорта.

## Проверка

### Три команды — в чекауте `goo-fashion`

```
npx tsc --noEmit    exit 0, чисто
npm run build       exit 0, оба маршрута в выводе
npx eslint          exit 1 — 13 ошибок / 52 предупреждения
```

`eslint` был красным **до** меня: те же 13 ошибок в 19 чужих файлах
(`parallax-floating.tsx`, `ProductCard.tsx`, `goo-studio/layout.tsx` …) на чистом
`master`. Чинить их — это расширение объёма, запрещённое `CLAUDE.md` и разделом 11
`DESIGN_SYSTEM.md`. Поэтому критерий: **база не выросла**. До и после — ровно
13/52, по моим файлам и по `extension/` — ноль (`npx eslint extension` → exit 0).

### 39/39 — настоящие модули, `verification/test-server-logic.js`

Длиннейшее совпадение, ничья в пользу Allow, пустой `Disallow:`, `*` и `$`,
слитые группы агентов, robots.txt отданный HTML-страницей, пол и потолок паузы,
дедуп по `seen`, индекс → дети, потолок лимита.

### 27/27 — настоящее расширение в настоящем Chromium, `verification/run.js`

Против фиктивного магазина (`store.js`) и заглушки Студии (`studio.js`), которая
внутри зовёт **настоящие** `planCollection` и `parsePage`. Полный вывод —
`verification/e2e-output.txt`.

- при установке не выдан ни один хост: `explicit_host: []`, скриптуется только
  собственный экран приёмника, из API — `activeTab`, `scripting`, `storage`,
  `webRequest`;
- robots.txt прочитан первым, сайтмап — вторым кругом;
- запрещённый `/product/secret-*` не открыт ни разу и посчитан как `blocked`;
- темп 2 с взят из Crawl-delay магазина, разброс между запросами есть;
- страница ~430 КБ ужата до <300 КБ, JSON-LD цел, ленивая галерея приехала
  отрисованной (2 настоящих фото вместо data-URI), настоящий `parsePage` собрал
  товар из снятого DOM (имя, бренд, 249 EUR);
- на 403 прогон встал ровно после второй страницы, не третьей;
- после Stop — ни одного импорта и ни одного запроса в магазин;
- на 21 товаре без Crawl-delay применён пол 1.5 с, после двадцатой страницы лёг
  отдых 11 с.

## Что остаётся за вами

1. **Загрузить расширение и собрать настоящий магазин.** Это принципиально ваш
   шаг: у контейнера серверный IP — ровно тот, от которого мы и уходим. Ходить
   отсюда в живой магазин означало бы делать то, что задача запрещает.
   `chrome://extensions` → Режим разработчика → Загрузить распакованное →
   папка `extension/`.
2. **Приёмник должен быть открыт и залогинен.** Он зовёт API вашей сессией
   Clerk, подменить её я не могу. Вкладку, открытую до установки расширения,
   надо перезагрузить — иначе content script в неё не попадёт.
3. **Домен Студии** в popup по умолчанию `https://www.goo-fashion.com`;
   для локальной разработки впишите свой `http://localhost:3000`.

Что я проверить не мог, кроме живого магазина: сам диалог выдачи доступа
(`chrome.permissions.request` требует клика, headless его не даёт). Проверено
всё, что после него, а факт «при установке хостов ноль» снят из профиля Chrome.
